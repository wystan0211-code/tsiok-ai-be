# 九愛！買 Tsiok ài bé

園遊會攤位的預先點餐網站。顧客掃描 QR code 預點，攤位接單後顯示製作進度，餐點完成時通知顧客取餐。現場點餐也在同一套系統記帳，所有訂單自動同步到 Google 試算表。

全部使用免費方案：網站放在 GitHub Pages，資料存在 Firebase(Spark 免費方案)，推播與試算表同步由 Google Apps Script 處理。

## 功能

### 點餐者

- 掃描攤位 QR code 進入入口頁，產生一次性點餐連結(無法分享給別人使用)
- 瀏覽菜單、選擇口味、加入購物車；購物車與填寫中的資料重新整理不會消失
- 填寫姓氏與手機號碼，勾選取餐通知同意後送出
- 訂單進度頁：進度條、預估完成時間、攤位訊息、提示音與震動
- 開啟推播通知(Android 可直接開啟；iPhone 需先加入主畫面，iOS 16.4 以上)
- 攤位接單前可以取消；可用「訂單編號 + 電話」找回訂單

### 攤位(店員以上)

- 看板：新訂單、製作中、可取餐、今日已結束，卡片可展開查看明細與電話
- 接單、拒絕(附原因)、完成並通知取餐、退回製作中、已取餐收款
- 傳訊息給顧客(常用訊息範本)、半自動簡訊通知(開啟店員手機的簡訊 App 並帶入內容)
- 新訂單提示音、逾時未取餐提醒
- 現場點餐：立即取餐直接記帳；稍後取餐產生 B 開頭編號與 QR code，顧客掃描可追蹤進度
- 收件匣：顧客預點超過上限時自動拒絕並通知
- 取餐核對：用訂單編號或電話末三碼查詢
- 叫號大螢幕(display.html)

### 後台

- 攤位主管：品項管理(價格、說明、圖片、口味、數量上限、上下架、售完)、營業設定(公告、接受預點、數量上限、訊息範本、簡訊範本、同意文字)、收支查詢與 CSV 匯出(唯讀)
- 管理員：以上全部，加上收支編輯、刪除、手動新增，員工帳號管理，訂單編號歸零，列印點餐 QR code

### 權限

| 功能 | 店員 | 攤位主管 | 管理員 |
|---|---|---|---|
| 營運頁、現場點餐、叫號畫面 | 可以 | 可以 | 可以 |
| 暫停或開始接受預點 | 可以 | 可以 | 可以 |
| 品項與營業設定 | 不行 | 可以 | 可以 |
| 查看收支、匯出 CSV | 不行 | 可以 | 可以 |
| 編輯、刪除、新增收支 | 不行 | 不行 | 可以 |
| 員工帳號管理 | 不行 | 不行 | 可以 |

## 本機預覽(展示模式)

`js/config.js` 的 Firebase 設定還沒填時，網站會以「展示模式」運作：資料只存在目前的瀏覽器，不需要任何帳號就能試用完整流程。同一個瀏覽器開多個分頁會即時同步，可以一個分頁當顧客、一個分頁當攤位。

網站使用 JavaScript 模組，**不能直接雙擊 HTML 開啟**，必須用本機伺服器：

- VS Code：安裝 Live Server 擴充功能，在 index.html 按右鍵選「Open with Live Server」
- 或在終端機進入專案資料夾執行 `python3 -m http.server 8000`，再開啟 http://localhost:8000

展示模式帳號：

| 權限 | 帳號 | 密碼 |
|---|---|---|
| 管理員 | admin | admin1234 |
| 攤位主管 | manager | manager1234 |
| 店員 | staff | staff1234 |

展示模式不支援推播與 Google 試算表。後台「系統」分頁可以重設展示資料。

## 發布教程

以下步驟全部免費，不需要綁定信用卡。建議依序完成，每一步完成後再進行下一步。

### 1. 建立 Firebase 專案

1. 到 https://console.firebase.google.com 建立專案(名稱例如 tsiok-ai-be，Google Analytics 可以關閉)。
2. 專案總覽點「網頁」圖示新增應用程式，暱稱隨意，不需要勾選 Firebase Hosting。
3. 畫面會出現 `firebaseConfig`，把裡面六個欄位複製到 `js/config.js` 的 `firebase` 區塊。

### 2. 設定登入方式與管理員

1. 左側「Authentication」>「開始使用」>「登入方式」，啟用「匿名」與「電子郵件/密碼」。
2. 「使用者」>「新增使用者」，Email 填 `admin@tsiokaibe.example.com`，密碼自訂(至少 8 字)。
	- 登入時帳號只要輸入 `admin`，系統會自動補上網域。
	- example.com 是保留給範例使用的網域，不會寄出任何信件。
3. 複製這個使用者的「使用者 UID」，貼到三個地方：
	- `js/config.js` 的 `adminUid`
	- `firestore.rules` 的 `adminUid()`(取代 `REPLACE_WITH_ADMIN_UID`)
	- 第 6 步 Apps Script 的指令碼屬性 `ADMIN_UID`

### 3. 建立 Firestore 資料庫

1. 左側「Firestore Database」>「建立資料庫」，選「正式版模式」，位置建議選 `asia-east1`(台灣)，建立後無法更改。
2. 「規則」分頁：刪除原有內容，貼上整份 `firestore.rules`(已填好管理員 UID)，按「發布」。
	- 發布時如果出現錯誤訊息，請把訊息完整複製給我。

### 4. 取得推播憑證

1. 左上齒輪 >「專案設定」>「雲端通訊」。
2. 最下方「網頁設定」>「網頁推播憑證」> 產生金鑰組，把金鑰貼到 `js/config.js` 的 `vapidKey`。

### 5. 下載服務帳戶金鑰(機密)

1. 「專案設定」>「服務帳戶」>「產生新的私密金鑰」，會下載一個 JSON 檔。
2. **這個檔案等同最高權限的鑰匙，絕對不能上傳到 GitHub 或傳給別人。** 它只會貼進 Apps Script 的指令碼屬性。用完後可以刪除電腦上的檔案。

### 6. 建立試算表與 Apps Script

1. 建立一份新的 Google 試算表，名稱例如「九愛買訂單」。
2. 「擴充功能」>「Apps Script」，刪除預設內容，貼上整份 `apps-script/Code.gs`，按儲存。
3. 左側齒輪「專案設定」> 最下方「指令碼屬性」，新增以下六個屬性：

| 屬性 | 內容 |
|---|---|
| SERVICE_ACCOUNT | 第 5 步 JSON 檔的完整內容(整個檔案複製貼上) |
| PROJECT_ID | Firebase 專案 ID(專案設定 > 一般) |
| API_KEY | 與 `js/config.js` 的 apiKey 相同 |
| ADMIN_UID | 第 2 步的管理員 UID |
| SITE_URL | 網站網址，結尾要有 `/`，第 7 步完成後再填也可以 |
| EMAIL_DOMAIN | `tsiokaibe.example.com` |

4. 回到編輯器，上方函式選單選 `setup`，按「執行」。第一次會要求授權，依畫面允許。
	- 若出現「Google 尚未驗證這個應用程式」，點「進階」>「前往(不安全)」。這是你自己的指令碼，所以會出現這個提示。
	- 執行成功後，試算表會出現「訂單」工作表，並建立每分鐘同步的觸發條件。
5. 右上「部署」>「新增部署作業」> 類型選「網頁應用程式」：
	- 執行身分：我
	- 存取權：所有人
6. 部署後複製網址(以 `/exec` 結尾)，貼到 `js/config.js` 的 `appsScriptUrl`。
7. 試算表的「共用」只給管理員編輯權限。**不要手動修改「訂單」工作表**，同步時會被覆蓋；需要註記請另外新增工作表。
8. 之後若修改 Code.gs，要到「部署」>「管理部署作業」> 編輯 > 版本選「新版本」再部署，網址不會變。

### 7. 發布到 GitHub Pages

1. 在 GitHub 建立**公開** repository，名稱 `tsiok-ai-be`(免費帳號的 GitHub Pages 需要公開 repo)。
2. 上傳整個專案資料夾的內容(包含 `.gitignore`)，不要上傳服務帳戶 JSON 檔。
	- `js/config.js` 裡的資料都是公開資訊，可以上傳；安全性由 firestore.rules 把關。
3. repository 的「Settings」>「Pages」> Source 選「Deploy from a branch」，Branch 選 `main`、資料夾 `/(root)`，儲存。
4. 約一分鐘後網址會是 `https://你的帳號.github.io/tsiok-ai-be/`，把它填進第 6 步的 `SITE_URL`。

### 8. 允許網站使用 Firebase 登入

Firebase「Authentication」>「設定」>「已授權網域」> 新增 `你的帳號.github.io`。沒有這一步，員工會無法登入。

### 9. 開始使用

1. 開啟 `https://你的帳號.github.io/tsiok-ai-be/login.html`，用 `admin` 登入。
2. 進入後台(營運頁右上的齒輪)，系統會自動建立營業設定。
3. 新增品項、檢查營業設定。
4. 「帳號」分頁建立店員與攤位主管帳號。
5. 「系統」分頁列印點餐 QR code，貼在攤位。

### 10. 正式營業前的測試清單

建議用兩支手機實際測試，一支當顧客、一支當攤位：

- [ ] 顧客掃描 QR code → 點餐 → 送出，攤位看板出現新訂單並有提示音
- [ ] 接單 → 顧客頁面變成「製作中」並顯示預估時間
- [ ] 傳訊息 → 顧客頁面即時出現
- [ ] Android 顧客開啟通知後，把瀏覽器切到背景，攤位按「完成，通知取餐」→ 顧客收到推播
- [ ] iPhone 顧客加入主畫面後開啟通知，重複上一項
- [ ] 簡訊通知按鈕能開啟簡訊 App 並帶入內容
- [ ] 預點超過 10 件 → 收件匣出現通知
- [ ] 現場點餐「稍後取餐」→ 顧客掃描 QR code 能看到進度
- [ ] 約 1 到 2 分鐘後，Google 試算表出現訂單
- [ ] 店員帳號無法進入後台；攤位主管無法編輯收支

任何一項失敗時，請在電腦版 Chrome 按 F12 開啟「Console」，把紅色錯誤訊息截圖給我。

## 通知機制

| 方式 | 條件 | 說明 |
|---|---|---|
| 頁面即時更新 | 顧客開著訂單頁 | 狀態、訊息即時顯示，並播放提示音與震動(iPhone 不支援震動) |
| 推播通知 | 顧客按「開啟取餐通知」 | 瀏覽器在背景也會收到；iPhone 必須先加入主畫面 |
| 簡訊 | 店員手動按「簡訊通知」 | 開啟店員手機的簡訊 App 並帶入內容，由店員按下傳送，費用依店員的電信方案 |

提示音需要使用者先點一下畫面才能播放，這是瀏覽器的規定。攤位頁面開啟後請先點一下畫面。

## 免費額度

以下數字為撰寫時的官方額度，實際以 Google 官方頁面為準：

- Firestore：每天讀取 5 萬次、寫入 2 萬次、儲存 1 GiB。依約 30 人同時使用的規模估算，一般營業日在額度內。超過時當天會暫停服務到隔天，不會收費。
- Apps Script：免費帳號的觸發條件每天總執行時間上限約 90 分鐘。每分鐘同步一次通常足夠；若 Apps Script 顯示超過配額，可到「觸發條件」改成每 5 分鐘一次。
- Firebase Cloud Messaging 推播：免費。
- Cloud Storage 自 2026 年 2 月起需要付費方案，所以品項圖片壓縮後直接存在 Firestore(每張約 250 KB 以內)。

## 資料與隱私

- 顧客只需勾選「取餐通知」的同意，同意文字可在後台修改。電話只有員工與下單者本人能讀取。
- 資料不會自動刪除，會保留在 Firestore 與試算表中。若之後要把資料用於通知以外的用途(例如問卷調查)，這次的同意並不涵蓋，建議事先修改同意文字並與學校確認。
- 訂單 ID 是隨機長字串，持有訂單連結的人可以看到該筆訂單的姓氏與品項(看不到電話)。請提醒顧客不要公開分享訂單頁網址。
- 收支刪除為「標示刪除」，資料仍保留並在試算表顯示「已刪除」，方便事後查帳。

## 已知限制

- **Firebase 正式模式尚未實際測試**：安全規則、Apps Script、推播、帳號管理 API 都無法在開發環境連線測試，只驗證過語法。展示模式的完整流程已測試通過。部署後請依測試清單檢查。
- Firebase SDK 使用 gstatic CDN 的 12.19.0 版，開發環境無法連線確認該版本檔案存在；若頁面出現載入失敗，可把 `js/config.js` 的 `firebaseSdkVersion` 改成 Firebase 官網顯示的版本。
- 網路中斷時，一般操作(接單、完成)會暫存並在恢復連線後上傳；但**建立新訂單需要連線**才能取得編號。
- 試算表約有 1 分鐘延遲，只能在網站修改資料，試算表上的手動修改會被覆蓋。
- 同一個瀏覽器同時只能登入一個員工帳號；在另一個分頁登入別的帳號，原本的分頁會被登出。
- iPhone 加入主畫面後的 App 與 Safari 是分開的儲存空間，所以加入主畫面後會從訂單進度頁重新開啟；「訂單紀錄」只會出現在下單的那個瀏覽器。
- 簡訊按鈕使用 `sms:` 連結，各廠牌手機的簡訊 App 相容性不同，請營業前實測。
